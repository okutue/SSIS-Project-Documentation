# Neo4j lineage graph schema

Import scripts are generated by `OutputGenerator.GenerateCypher()` as `lineage.cypher`.

## Node labels

| Label | Key | Properties |
|-------|-----|------------|
| `Package` | `id` | `name`, `path` |
| `Task` | `id` | `name`, `type` |
| `Component` | `id` | `name`, `type`, `sql` |

## Relationships

| Type | From → To | Properties |
|------|-----------|------------|
| `BELONGS_TO` | Task → Package | — |
| `BELONGS_TO` | Component → Task | — |
| `PRECEDES` | Task → Task | `value`, `expr` (precedence constraint) |
| `FLOWS_TO` | Component → Component | — (data flow path) |
| `MAPS_TO` | Component → Component | `srcCol`, `destCol`, `expr`, `opType` (column lineage) |

## Import

```bash
cypher-shell -u neo4j -p <password> -f lineage-output/lineage.cypher
```

Or paste into Neo4j Browser. Run against a dedicated database; the script creates uniqueness constraints on `Package`, `Task`, and `Component` `id` properties.

## Example queries

```cypher
// Packages and their tasks
MATCH (p:Package)<-[:BELONGS_TO]-(t:Task) RETURN p.name, collect(t.name);

// Data flow between components
MATCH (a:Component)-[:FLOWS_TO]->(b:Component) RETURN a.name, b.name LIMIT 50;

// Column-level mapping
MATCH (a:Component)-[m:MAPS_TO]->(b:Component)
RETURN a.name, m.srcCol, b.name, m.destCol LIMIT 50;
```
